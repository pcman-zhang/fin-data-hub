# 通知与告警渠道（飞书等，暂不制作）

> 状态：**暂不制作**（增强功能） | 关联：doc-14（WebUI）、doc-13 §3.4、TASK-3.5（质量）/TASK-3.6（调度）/TASK-4.1（对账）
> 触发条件：需要**主动通知**（而非登录 WebUI 查看）时启用；渠道以飞书为首选，预留邮件与通用 Webhook。

## 1. 通知场景与优先级

| 级别 | 场景 | 来源 |
|---|---|---|
| 高 | 任务连续失败 N 次 | 调度（TASK-3.6） |
| 高 | SLA 违约（lag 超容忍 / 期望日期缺失） | 新鲜度水位（doc-13、TASK-3.6） |
| 高 | 质量门禁失败 / 对账差异超阈值 | 质量（TASK-3.5）、对账（TASK-4.1） |
| 中 | 数据代次切换完成 / 回填·重算完成 | 派生与存储（TASK-3.12/3.3） |
| 低 | 每日数据面健康摘要 | 总览 |

## 2. 渠道抽象

- `Notifier` 接口：`send(message) -> result`；实现：
  - **飞书**（自定义机器人 Webhook / 应用消息）；
  - 邮件（SMTP）；
  - 通用 Webhook（JSON POST，便于对接其他 IM）；
- 渠道与阈值由配置注入（凭证不落仓库/镜像）；支持**静默窗口**与启停开关。

## 3. 消息规范

- 字段：级别 / 数据集 / 时间 / 指标值（lag、差异、行数）/ `request_id` / 可选 WebUI 跳转链接；
- **去重与聚合**：同 key 在窗口期内合并（如 5 分钟）；防轰炸限速；
- 模板按级别着色（高=红、中=黄、低=灰，具体随渠道能力）。

## 4. 触发来源

- 调度事件（job 开始/结束/失败）、质量检查结果、新鲜度检查、对账任务 → 统一 `NotificationService`；
- 与 WebUI 解耦：通知可用、WebUI 不可用不影响告警。

## 5. 安全与合规

- Webhook/邮箱凭证仅配置注入；消息内容裁剪（不含凭证/内部路径）；
- 发送失败重试 + 失败降级日志；不做跨渠道静默回退（显式配置）。

## 6. 实施清单（未来启用时）

1. `Notifier` 抽象与飞书适配器；2. 规则/阈值配置（复用字典 SLA 与质量规则）；3. 去重/静默/限速；4. 消息模板与测试；5. mock Webhook 集成测试。
